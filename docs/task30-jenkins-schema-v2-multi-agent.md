# Task 30: Jenkins schema-v2 physical multi-agent ASM validation

Task 30 was validated in the existing Docker Jenkins POC with Jenkins 2.516.2 and PetClinic `88e37c15cf6fc8490b01bc3e8e2c800cec1ac272`. Full evidence is Jenkins build 10; build 9 was the bounded continuation that proved corrected shard filtering before the application coverage include was added.

The old boundary was schema-v1-specific: `stpCoverageMap` always installed the bundled JaCoCo init script and parsed JSON itself with a hard `schemaVersion == 1` check; `stpPublishCoverageMap` invoked a bundled runtime compiled against the schema-v1 common artifact. `stpPrepareCoverageMapping` owned revision, inventory, shard count, assignments and fragment paths and did not derive expectation from fragments. Local publication wrote only below the join agent's `~/.gradle/smart-test-picker` POC directory.

The public step names remain unchanged. `stpCoverageMap` now defaults `collector` to `ASM`, accepts only `ASM` or `JACOCO`, and optionally accepts comma-separated `coverageIncludes`. ASM uses a separate init script which applies the production Gradle plugin, configures its extension, filters `generateSmartTestCoverage`, and copies the plugin-produced fragment and diagnostic. It never injects a javaagent or calls collector APIs. JACOCO remains isolated on the historical init-script/runtime path. Fragment acceptance and join use `CoverageFragmentCodec`, `CollectionExpectation`, `CollectionSummary`, `Completeness`, and `CoverageMapValidator` from `smart-test-picker-common`; Jenkins has no schema parser.

Independent Jenkins inventory found 73 logical cases: 69 runnable and four disabled database-profile cases. Only the 69 runnable identities form the expectation. Deterministic lifecycle-container sharding produced 32/12/25 cases on `stp-map-agent-1`, `-2`, and `-3`. Each emitted schema v2, the same revision, its unique shard, `collection.completed=true`, and a diagnostic; each stash transported only those two files.

The baseline and joined result both contain 69 mapped tests, zero unmapped tests, 418 class edges, 1,343 method edges, and ten setup scopes. Exact normalized test, class, method, setup, outcome, collection-status and unmapped semantics had zero differences. No run-wide Cartesian attribution occurred, and the historical `CacheConfiguration`, `CrashController`, or `WelcomeController` to `ValidatorTests` false relations are absent. Diagnostics contain no agent errors, transformation failures, method-ID collisions, runtime-init failures, fragment failures, unsupported identities, or late events. `NO_ACTIVE_TEST` observations remain diagnostic-only.

Controlled joins rejected a missing shard, duplicate shard, revision mismatch, missing expected test, and unexpected test, producing no map. Agent termination was not run because it was disruptive; missing-fragment rejection covers the same publication safety boundary.

This proves schema-v2 ASM orchestration, physical stash/unstash, completeness and local POC publication. It does not add remote storage, retention, selector changes, Maven integration, or production scheduling. Backlog 5c remains IN PROGRESS and 5d remains NOT STARTED — POC proven.
