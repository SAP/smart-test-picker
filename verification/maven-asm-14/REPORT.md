# MAVEN-ASM-14: PetClinic attribution across deterministic method orders

## Result

ASM was order-invariant in all three measured permutations. JaCoCo was also
order-invariant. The differential found **no natural cross-boundary movement**
of per-test method edges in this sequential, 69-test PetClinic scope.

| Collector | MethodName edges | Random 8675309 edges | Random 20261104 edges | Stable across all orders | Variable edges | Methods with changed owners |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ASM | 1,343 | 1,343 | 1,343 | 1,343 | 0 | 0 |
| JaCoCo | 1,400 | 1,400 | 1,400 | 1,400 | 0 | 0 |

These are exact `(executable test identity, descriptor-qualified method)` set
comparisons, not a comparison of counts alone. All six runs passed all 69 tests
(414 passing test executions). All assignments were fully accounted for, with
no unmapped or positively non-executed identities. Production fragment,
aggregation and join validation succeeded.

**Answer A at the observed differential level:** no category-(c) movers were
found. The temporal-isolation assumption was not contradicted by these runs.
That is not proof that the assumption always holds: consistently wrong
attribution can remain order-stable, and three permutations cannot establish
universal soundness. This measurement supplies no natural-bleed finding that
would itself require re-deriving published numbers; it does not clear all
published results or estimate how many might be affected. The engineered
counterexamples in ASM-13 remain valid.

The two collectors are **not claimed equivalent**. Their stable leaf edge sets
have different sizes. This task compares each collector against itself, not
against a presumed common attribution truth.

Actual testcase sequences in retained Surefire XML differ across all three
permutations and match exactly between collectors for each permutation. The

MethodName order. For example, `PetClinicIntegrationTests` runs

Positions mean positions within the declaring test class, as emitted in the
sequential Surefire report, not an independently observed global callback
timeline. Class order was held fixed. A reverse custom orderer was unnecessary:
two fixed random seeds plus MethodName establish the required three distinct
method permutations without adding a subject class.

## Differential and classification

Rules were fixed in [PRE-RUN.md](PRE-RUN.md), before inspecting results:

1. A stable edge belongs to the intersection of the three exact edge sets.
   A variable edge belongs to their union minus intersection. Appearance or
   disappearance is retained, not silently treated as an owner transfer.
2. Category (a) requires a static initializer or positive source/bytecode proof
   that coverage is class-init-only. Constructors are not automatically (a).
3. Category (b) requires positive evidence of once-per-JVM/context bootstrap;
   first position alone is insufficient.
4. Category (c) is a varying ordinary application method with an ordinary caller,
   not established as (a) or (b). Even then, a causal bleed claim must distinguish
   shared-state or caching effects from time-window misattribution.

| Collector | (a) variable edges / methods | (b) variable edges / methods | (c) variable edges / methods | Unclassified movers |
| --- | ---: | ---: | ---: | ---: |
| ASM | 0 / 0 | 0 / 0 | 0 / 0 | 0 |
| JaCoCo | 0 / 0 | 0 / 0 | 0 / 0 | 0 |

These zeros classify **movers**, not all covered methods. There are no movers to
name or test for position-following ownership, and no observed method/test pair
for an unsafe-selection counterexample. Position-following is therefore **not
observed**, not disproven for arbitrary runs.

Each JaCoCo run retains **87 raw sessions: 69 leaf and 18 setup sessions**.
SessionOracle reads the original `.exec` files against the retained original
production classes and their identity/setup sidecars. Exact leaf tables match
the production fragments. Raw setup method sets also remain invariant across
the three JaCoCo orders. Production setup scopes are invariant within each
collector. Setup class scopes are kept separate rather than expanded into
invented per-test method edges.

The full stable edge tables, actual orders, empty variable-edge/owner-change
ledgers and setup comparisons are in [raw/differential.json](raw/differential.json).
The executable checks are in [Differential.java](Differential.java), with output
in [differential.log](differential.log).

## Limits and carry-over

This is one run per configuration, three within-class method permutations,
fixed class order, one subject/revision and H2 scope. It is not a timing stress
test, repeated same-order sampling, global class-order permutation, mutation
campaign or measurement of selection inclusiveness. No new shared-context
scenario was introduced. Stable set-valued attribution cannot prove absence of
all asynchronous work or consistently misplaced edges.

No category-(c) movers were found, so the conditional future evaluation-harness
carry-over proposal is not triggered. No harness, paper, dataset, release binary,
guard, collector or other production code was changed. No Jenkins run was made.
The existing baseline suites were **not rerun**, because this task only adds
measurement files; prior suite counts are not presented as fresh results.

The bounded question is answered: **JaCoCo and ASM per-test method attribution
were both stable under these three genuinely different sequential method orders.**
